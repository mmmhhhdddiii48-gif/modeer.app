# معمارية Stage06 — Invoice Approval & Debt Ledger Contract

## الهدف

تحويل مسودة الفاتورة المراجَعة إلى فاتورة معتمدة وفتح ذمة المشترك بصورة ثابتة وقابلة للتدقيق، دون فتح التحصيل أو الوصولات أو أثر الصندوق.

## شرط الاعتماد

- يجب أن تكون المسودة بحالة `reviewed`.
- الاعتماد يحتاج `confirm=true`.
- مسودة `draft` لا يمكن اعتمادها.
- الفاتورة تُنشأ مرة واحدة فقط لكل مسودة ولكل مشترك داخل الدورة.

## generator_invoices

يحفظ Snapshot كاملًا من المسودة: الفترة، المشترك، الحساب، العداد، المولدة، الأمبير، التسعيرة، القراءة السابقة والحالية، الاستهلاك والمبلغ.

- الحالة الوحيدة في Stage06 هي `approved`.
- رقم الفاتورة فريد داخل Tenant.
- الفاتورة غير قابلة للتعديل أو الحذف.

## generator_debt_ledger_entries

سجل append-only للذمم. عند اعتماد الفاتورة يضاف قيد `invoice_debit`:

- المدين = مبلغ الفاتورة.
- الدائن = صفر.
- الرصيد بعد القيد = رصيد المشترك السابق + مبلغ الفاتورة.
- لا يتم إنشاء قيد قبض أو وصل.

المخطط يسمح بأنواع مستقبلية مثل `payment_credit`، لكن Stage06 لا يملك أي Endpoint لإنشائها.

## Idempotency

إعادة اعتماد نفس المسودة تعيد نفس الفاتورة وقيدها دون تكرار. القيود الفريدة والمعاملة `BEGIN IMMEDIATE` تحمي من السباق.

## عزل المؤسسات

كل الاستعلامات والكتابات تستخدم `tenantId` من Access Token. لا يقبل السيرفر Tenant من Body ولا يمكن اعتماد مسودة أو رؤية فاتورة من مؤسسة ثانية.

## الحدود

- لا قبض كامل أو جزئي.
- لا وصولات.
- لا صندوق أو درج نقدي.
- لا إلغاء أو حذف فاتورة.
- لا تعديل قيد ذمة.
- لا وصول للجابي إلى الفواتير أو الذمم.
